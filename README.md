# 三进制 vs 二进制 · GPU 位并行筛选

同一份 Rust 代码、同一个 GPU、同一条查询，只换数据表示。

## 结果（1000 万对象，120 MB，超出 L2）

| 实现 | 每对象表示 | 线程粒度 | 耗时/次 | 吞吐 | 带宽/次 |
|---|---|---|---:|---:|---:|
| **BINARY** | 3 个 f32 | 1 个对象 | 0.75 ~ 3.08 ms | 3.2 ~ 13.4 G 对象/s | **120 MB** |
| **TERNARY** | 6 bit（pos/neg 位平面） | **32 个对象** | 0.023 ~ 0.132 ms | 76 ~ 426 G 对象/s | **3.75 MB** |

**23 ~ 106× 快，中位约 32×。**

这个 32 正好是两个东西的比值：

- **存储密度**：120 MB ÷ 3.75 MB = **32×**
- **位并行度**：一个 `u32` 一次判 32 个对象

命中数两版完全一致（**740,036**），不是偷工减料。

波动来源：BINARY 每次要读 120 MB，耗时随显存带宽/缓存状态在 0.75~3.08 ms 之间摆；TERNARY 只读 3.75 MB，稳定落在 L2 里。

## 关键：数据必须超出 L2

| 对象数 | BINARY 数据量 | 倍数 |
|---:|---:|---:|
| 100 万 | 12 MB（**在 L2 内**） | **1.92×** |
| 1000 万 | 120 MB（**超出 L2**） | **23 ~ 106×** |

12 MB 时，4060 Ti 的 L2（32 MB）把整个数据集接住了，二进制版根本没被显存带宽卡住——三进制的存储密度优势无处兑现。

**把数据推出 L2，差距立刻拉开一个数量级。** 这是这次实验最重要的结论。

## 直观对比

打开 `index.html`（WebGPU 页面，建议用本地 http 打开，如 `python -m http.server`）：

- 三进制跑 **十亿对象**（375 MB，整卡放得下）；二进制受 8 GB 显存限制，取 1.5 亿对象（1.8 GB）
- 每个面板实时显示每次 dispatch 的 ms、G 对象/s、带宽/次
- 连续背靠背提交、不等 vsync——运行期间 GPU 持续满载（4060 Ti 实测 99~100%、约 98 W）

另有一个 **毒蘑菇分形页** `mushroom.html`：移植 cznull volumeshader_bm 的同款内核（球坐标折叠 8 次幂分形 + 二分求交），可自由转镜头。
- 低 / 中 / 高 三档强度；4060 Ti 实测：中档 60 FPS、高档 18 FPS
- 运行期间 GPU 85~93%、约 142 W（接近 160 W 功耗墙）
- 地址：<https://bfxh.github.io/trit-vs-binary/mushroom.html>

### 原生 Rust 对照（Vulkan，离屏，不锁 vsync）

`cargo run --release --bin mushroom_bench`，879×681，与网页同一份 WGSL：

| 档位 | 原生 Rust（Vulkan） | 网页（D3D12） |
|---|---:|---:|
| 低（3 迭代 / 8 幂） | 9.8–10.2 ms · ~100 FPS | 60 FPS（vsync 上限） |
| 中（4 迭代 / 8 幂） | 16.2 ms · ~61.6 FPS | 60 FPS（vsync 上限） |
| 高（100 迭代 / 10 幂） | 62.1 ms · 16.1 FPS | 18 FPS（GPU 瓶颈） |

结论：网页与原生在 ±15% 以内，瓶颈始终是 GPU 的逐像素分形求交。
这个负载是纯浮点/三角函数，**没有三进制版本**；三进制能切入的是
“把分形预先体素化成占据网格，再用位平面做 DDA 跳空”，属于另一个实验。

### 分形体素化 + 三进制位平面 DDA（voxel.html）

`voxel.html` 把同一颗分形 SDF 在 GPU 上预采样成 512³ 占据网格（体素化约 50–60 ms，一次性）：

- 三态：表面 +1 / 内部 0 / 空 -1；**2 个位平面**（实心 + 表面），2 bit/体素 = **33.6 MB**
- 二进制对照：1 字节枚举 = **134.2 MB**
- DDA：8³ 粗格跳空 + 细步逐体素；三进制只读实心平面（每步 1 个 word + 1 次位测试）

4060 Ti 实测（交替多轮取中位；页面 HUD 实时显示）：

| 设置 | 三进制 | 二进制 | 相对 |
|---|---:|---:|---:|
| 粗格跳空开（640×360 × 160 次 × 9 轮） | 0.129–0.132 ms | 0.129–0.138 ms | 1.00–1.04× |
| 粗格跳空关 / 纯细步（480×270 × 20 次 × 7 轮） | 0.555 ms | 0.700–0.735 ms | **1.26–1.32×** |

纯细步平均约 **526 步/射线**。去掉粗格后三进制领先 **26–32%**：每条射线都要逐体素
扫过大量空域，位平面的 4× 内存密度开始兑现；但差距仍远小于 4×，因为 DDA 同时
受步进次数与缓存延迟限制。命中校验：两种表示的光线命中哈希完全一致。

页面 HUD 实时显示：**FPS、GPU ms/帧、本页显存、当前表示的读放大**，以及
「粗格 / 纯细步」两套 A/B 时间；「粗格跳空」按钮可以在画面上现场开关对比。

地址：<https://bfxh.github.io/trit-vs-binary/voxel.html>

## 运行要求（重要）

- 需要一台带**高性能独立显卡**的机器：建议 8 GB 以上显存、Chrome / Edge 113+ 且开启硬件加速
- 默认模式会占用约 **3–4 GB 显存**、持续把 GPU 压到 100%（4060 Ti 实测约 98 W）
- 核显 / 小显存 / 老驱动可能初始化失败、卡顿或驱动重置——真崩了也不怪谁，关掉页面就好
- 初始化失败或带宽异常时，页面会自己停下来并给出提示，可点「轻量模式（1 亿对象）」重试
- **关闭页面后显存与 GPU 占用立即释放**，不留后台进程；也可以长时间挂着跑

## 实现

查询：`a == True && b == True && c != False`（3 个三值条件）

**BINARY**（纯 f32，无任何三进制依赖）：

```wgsl
if (a[i] > 0.5 && b[i] > 0.5 && c[i] > -0.5) {
    atomicAdd(&counter, 1u);
}
```

**TERNARY**（位平面，一个线程处理 32 个）：

```wgsl
let bits = pa[w] & pb[w] & ~nc[w];
let n = countOneBits(bits);
if (n > 0u) { atomicAdd(&counter, n); }
```

## 测量口径与踩过的坑

- **批量 dispatch**：200 次 dispatch 后统一 `poll(Wait)`，不在每轮里 `clear/copy/poll`。
  每轮的固定开销约 0.1 ms，会把差异完全盖住——初版就是这样，100 万对象时只测出 1.15×。
- **位平面用 32 位字**：`1u32 << (i % 64)` 会溢出（u32 只有 32 位），
  初版因此少算了 5675 个对象。改成 32 位字后正确性通过。
- **带宽显示按实际计算**：`N × 12` 字节（binary）、`N × 12 / 32` 字节（ternary）。
