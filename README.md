# 三进制 vs 二进制 · GPU 位并行筛选

同一份 Rust 代码、同一个 GPU、同一条查询，只换数据表示。

## 结果（1000 万对象，120 MB，超出 L2）

| 实现 | 每对象表示 | 线程粒度 | 耗时/次 | 吞吐 | 带宽/次 |
|---|---|---|---:|---:|---:|
| **BINARY** | 3 个 f32 | 1 个对象 | 0.75 ~ 3.08 ms | 3.2 ~ 13.4 G 对象/s | **120 MB** |
| **TERNARY** | 6 bit（pos/neg 位平面） | **32 个对象** | 0.023 ~ 0.132 ms | 76 ~ 426 G 对象/s | **3.75 MB** |

**23 ~ 106× 快，中位约 32×。**

这个 32 正好是两个东西的比值：

- **存储密度**：120 MB ÷ 3.75 MB = **32×**
- **位并行度**：一个 `u32` 一次判 32 个对象

命中数两版完全一致（**740,036**），不是偷工减料。

波动来源：BINARY 每次要读 120 MB，耗时随显存带宽/缓存状态在 0.75~3.08 ms 之间摆；TERNARY 只读 3.75 MB，稳定落在 L2 里。

## 关键：数据必须超出 L2

| 对象数 | BINARY 数据量 | 倍数 |
|---:|---:|---:|
| 100 万 | 12 MB（**在 L2 内**） | **1.92×** |
| 1000 万 | 120 MB（**超出 L2**） | **23 ~ 106×** |

12 MB 时，4060 Ti 的 L2（32 MB）把整个数据集接住了，二进制版根本没被显存带宽卡住——三进制的存储密度优势无处兑现。

**把数据推出 L2，差距立刻拉开一个数量级。** 这是这次实验最重要的结论。

## 实现

查询：`a == True && b == True && c != False`（3 个三值条件）

**BINARY**（纯 f32，无任何三进制依赖）：

```wgsl
if (a[i] > 0.5 && b[i] > 0.5 && c[i] > -0.5) {
    atomicAdd(&counter, 1u);
}
```

**TERNARY**（位平面，一个线程处理 32 个）：

```wgsl
let bits = pa[w] & pb[w] & ~nc[w];
let n = countOneBits(bits);
if (n > 0u) { atomicAdd(&counter, n); }
```

## 测量口径与踩过的坑

- **批量 dispatch**：200 次 dispatch 后统一 `poll(Wait)`，不在每轮里 `clear/copy/poll`。
  每轮的固定开销约 0.1 ms，会把差异完全盖住——初版就是这样，100 万对象时只测出 1.15×。
- **位平面用 32 位字**：`1u32 << (i % 64)` 会溢出（u32 只有 32 位），
  初版因此少算了 5675 个对象。改成 32 位字后正确性通过。
- **带宽显示按实际计算**：`N × 12` 字节（binary）、`N × 12 / 32` 字节（ternary）。
